# 双色球选号研究平台：技术路线与迭代规划

## 一、V1功能与工程选型

初版使用 **标准HTML + CSS + JavaScript ES Module**，前端零依赖，不需要npm安装和构建，GitHub Pages可直接运行。Python标准库负责历史数据更新与质控，GitHub Actions执行离线更新与自动发布。相比先搭建Vue、服务端和数据库，零依赖可以降低首版上线风险；如果V2需要登录、多人协作和复杂图形，再迁移到Vue3 / Vite / ECharts，同时沿用`engine.js`纯算法模块。

### 系统边界

- 数据源：公开历史开奖，后续可以增加官方源校验。
- 算法：排除规则、选号组合模板、精确概率基准、滚动回测。
- 数据存储：只读静态JSON / CSV + 浏览器localStorage。
- 更新：开奖后GitHub Actions定时拉取并重新部署；用户也可触发实时远端刷新。

## 二、算法说明

双色球单期开奖样本空间：C(33,6)×16=17,721,088种，每个结果等概率。红球中任意一个号码的理论出现概率为6/33，蓝球任意号码为1/16。排除号码没有改变这些概率。

### 排除规则

1. **遗漏最长**：截至开奖前数据，距离最近一次出现的期数最长优先排除。
2. **30/100/300期冷号**：指定窗口内出现次数最少优先排除。
3. **30期热号**：指定窗口内出现次数最多优先排除。
4. **综合冷号评分**：频率与遗漏期数加权（实验指标，非真实概率）。

默认红球排除6个、蓝球排除2个；模板只要求不少于27个剩余红球和5个剩余蓝球。若候选池更大，则随机抽取符合模板结构的子集。

### 红球组合结构

5注共30个红球位置，通过固定模板保持27个不重复的红球，只有3个红球在两注间重复；任意两注相同红球不超过1个。模板上将数字做随机一一映射，保证概率结果不会因为数字标签变化而变化。

### 蓝球结构

- **中奖优先**：5蓝球分别不同，任意奖中奖事件更少重叠；
- **回本优先**：2+2+1，将至少两个六等奖合计10元的事件提升；
- **盈利优先**：3+2，其中一组三注六等奖合计15元提高盈利发生频率。

### 概率边界

当前发布版本中的中奖/回本/盈利概率是对上述固定交集模板进行全开奖结果精确枚举验证的**理论常量**。不允许在用户自行编辑票号或修改模板后仍原样使用。

一、二等奖为浮动奖，历史兑奖金额必须另据当期公告；当前程序仅对固定奖金作出明确数值核算。

## 三、数据流程与质量控制

- 获取JSON数据；解析日期、期号、红蓝球。
- 检查6个不同红球和一个蓝球的取值范围、重复期号/日期，按日期排序。
- 检查数据更新日期，确保新数据不会覆盖更完整的本地版本。
- 生成`history.json`，由GitHub Pages静态托管。
- 前端依次尝试本地完整数据 / 157期内置样本 / 在线直接补抓，明确标注样本限制。

## 四、测试与验收

- `tests/engine.test.mjs`覆盖杀号结果、不同策略、种子确定性、奖级、组合概率公式及回测。
- `tests/test_update_data.py`覆盖离线数据质量、重复记录、异常号码等。
- 网站功能：页面导航、刷新、选号、参数选择、复制、保存、导出、回测表及响应式布局。
- 浏览器视觉回归需要在浏览器可访问的部署或本地运行环境进一步确认。

## 五、V2可选增强

- 历史策略比较的置信区间与多重检验校正；
- 历史预测快照托管与跨设备同步（需后端及权限）；
- 用户手动圈选/锁定号码时即时调用组合概率引擎；
- 更自由注数 / 预算 / 蓝球分配，精确数学求解而不是沿用5注模板概率；
- 官方开奖数据交叉验证和异常告警；
- 概率目标从任意奖/回本/盈利扩展为奖金分布、极端波动与长期预算控制。
